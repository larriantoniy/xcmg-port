# Первый production deploy

Этот checklist выполняется вручную перед первым запуском и после него. Значения public environment variables встраиваются в статические страницы во время сборки, поэтому их нужно установить **до** `npm run build`.

## 1. Domain

- [ ] Выбрать основной HTTPS-домен.
- [ ] Настроить DNS для production hosting.
- [ ] Выбрать единственный canonical host (`www` или без `www`) и настроить постоянный redirect со второго варианта.
- [ ] Проверить действующий TLS-сертификат.
- [ ] Проверить production URL в `lib/site.ts` и при смене домена изменить его только там.

## 2. Environment variables

- [ ] Не добавлять secrets в публичную конфигурацию приложения.
- [ ] Пересобрать сайт после изменения production URL в `lib/site.ts`.

Production URL не зависит от environment variables: он хранится в `lib/site.ts` как единая статическая конфигурация и используется при сборке sitemap, robots, metadata и structured data.

Телефон, email, адрес и реквизиты хранятся в `data/company.ts` и не переопределяются environment variables. Перед deploy их необходимо ещё раз сверить с владельцем сайта и утверждёнными источниками.

## 3. Images

- [ ] Получить письменное разрешение или подтверждение прав на изображения.
- [ ] Поместить оптимизированные локальные файлы в каталог соответствующей модели: `public/images/products/<model>/`.
- [ ] Добавить главное изображение в `Product.media.hero`, остальные — в `Product.media.gallery`.
- [ ] Для каждого файла указать путь `/images/products/<model>/<file>`, точные `width`, `height` и содержательный русский `alt`.
- [ ] Не публиковать внешние или скопированные изображения без разрешения.
- [ ] Проверить отсутствие layout shift и корректный crop на mobile, tablet и desktop.

## 4. Build

- [ ] Выполнить `npm ci` в чистом окружении.
- [ ] Выполнить `npm run lint`.
- [ ] Выполнить `npm run typecheck`.
- [ ] Выполнить `npm test`.
- [ ] Выполнить `npm run build` с production environment variables.
- [ ] Убедиться, что сборка содержит `/`, `/richstackery/`, четыре страницы моделей, `/garantiya/`, `/about/`, `/contacts/`, `/sitemap.xml` и `/robots.txt`.

## 5. Deploy

- [ ] Развернуть production build на hosting platform.
- [ ] Проверить HTTP 200 для всех страниц из sitemap.
- [ ] Проверить настоящий HTTP 404 и `noindex` для несуществующего URL.
- [ ] Проверить переходы header, footer, breadcrumbs, CTA и ссылки между моделями.
- [ ] Проверить `tel:+79320199993` и `mailto:kra@xcmg.ru` во всех CTA, header и footer.
- [ ] Проверить адрес и маркер Яндекс Карты на `/contacts/`.
- [ ] Убедиться, что сайт работает без JavaScript-формы заявки.

## 6. SEO и indexability

- [ ] Открыть исходный HTML каждой страницы и проверить уникальные title, description, абсолютный canonical и Open Graph URL.
- [ ] Проверить structured data через валидатор Schema.org или Rich Results Test. Отсутствие `Offer` допустимо, пока коммерческие данные не подтверждены.
- [ ] Проверить, что canonical, structured data, sitemap и robots используют production-домен, а не `localhost`.
- [ ] Открыть `/robots.txt` и убедиться, что нужные страницы разрешены.
- [ ] Открыть `/sitemap.xml`, проверить все URL и отсутствие старых `/catalog` и `/portovaya-tehnika`.
- [ ] Проверить отсутствие `noindex` на индексируемых страницах.

## 7. Mobile и производительность

- [ ] Проверить вручную mobile примерно 360–430 px.
- [ ] Проверить tablet примерно 768–1024 px.
- [ ] Проверить desktop от 1280 px.
- [ ] Проверить горизонтальную прокрутку таблиц, навигацию, CTA и длинные характеристики.
- [ ] Запустить PageSpeed Insights для главной, категории и одной страницы модели.
- [ ] Проверить Core Web Vitals: LCP, INP и CLS.

## 8. Yandex

- [ ] Создать проект Яндекс Метрики и получить подтверждённый ID счётчика.
- [ ] Подключить Метрику отдельным изменением после согласования cookies/privacy требований.
- [ ] Добавить сайт в Яндекс Вебмастер и подтвердить права на домен.
- [ ] Отправить production URL `/sitemap.xml` в Яндекс Вебмастер.
- [ ] Проверить анализ `/robots.txt` в Яндекс Вебмастере.
- [ ] Запросить переобход главной, категории и четырёх страниц моделей.
- [ ] После индексации проверить диагностические сообщения, canonical и статус страниц.

## 9. Финальная проверка

- [ ] Проверить отображение на реальных мобильном и настольном устройствах.
- [ ] Проверить контактные и юридические сведения с владельцем сайта.
- [ ] Убедиться, что на сайте нет неподтверждённых цен, наличия, гарантий, сроков или статуса дилера.
- [ ] Зафиксировать дату deploy и сохранить результаты baseline PageSpeed/Core Web Vitals.
